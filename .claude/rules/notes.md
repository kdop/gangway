# Writing things down

- Do not implement or write a decision into a file until Kostas says "go", "do it" or "write it down". A question, an answer, a fact, a vent, exiting plan mode or approving a plan is not a go.
- Always ask or propose before writing notes, rules or instructions to a file that persists.
- Write only inside this git repo. Never in Claude's own hidden files elsewhere on the machine.
- Never write a memoir. Write the decision and its reason, or the open item, and nothing else: no "Kostas said", no "Claude proposed", no story of how the talk went, no dates inside the docs. This holds for every file, the notes too.
- Log only what will change a future decision and cannot be rebuilt from git, code or docs. Log once, when the discussion settles.
- When he approves a plan, commit and push the plan files only.
