## 2026-11-20 Design review: open items that are in no other file
*tags: review, mvp, requirements, tests, read-only, folder-grants, sudo, diff, backups, open-questions*

- The MVP scope is not decided. One proposal on the table: steps 1, 3 and 10 of `plan.md`, on one machine, no Tailscale yet.
- Wanted, after the MVP: paths passed straight at start, for example `gangway /var/log ~/app/config.yml`.
- Wanted, after the MVP: read-only mode. Commands on a built-in read-only list run with no prompt and are shown; anything else gets the normal prompt, so the AI can still fix what it finds. A strict form that refuses everything off the list could be a start option.
- Sudo is out of the MVP. Running the whole cli-tool as root is not decided: as root, a read-only command reads every secret on the host. Narrower ways: a group that may read the logs, or a sudo rule for single commands.
- Dropped for now: showing file changes as a diff.
- Backups of touched files are not possible for plain commands: the cli-tool cannot know what a command touches.
- Commands run with no terminal and no keyboard. Not in the docs yet: set `PAGER=cat` and `TERM=dumb`, and let the skill teach plain forms such as `top -b -n 1`.
- The GitHub description stays as it is: "Connect AI to any host, with guardrails built in."
