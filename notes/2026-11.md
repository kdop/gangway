## 2026-11-20 Design review: open items that are in no other file
*tags: review, mvp, requirements, tests, read-only, folder-grants, sudo, diff, backups, open-questions*

- The MVP scope is not decided. One proposal on the table: steps 1, 3 and 10 of `plan.md`, on one machine, no Tailscale yet.
- Wanted, after the MVP: paths passed straight at start, for example `gangway /var/log ~/app/config.yml`.
- Wanted, after the MVP: read-only mode. Commands on a built-in read-only list run with no prompt and are shown; anything else gets the normal prompt, so the AI can still fix what it finds. A strict form that refuses everything off the list could be a start option.
- Sudo is out of the MVP. Running the whole cli-tool as root is not decided: as root, a read-only command reads every secret on the host. Narrower ways: a group that may read the logs, or a sudo rule for single commands.
- Dropped for now: showing file changes as a diff.
- Backups of touched files are not possible for plain commands: the cli-tool cannot know what a command touches.
- Commands run with no terminal and no keyboard. Not in the docs yet: set `PAGER=cat` and `TERM=dumb`, and let the skill teach plain forms such as `top -b -n 1`.
- The GitHub description stays as it is: "Connect AI to any host, with guardrails built in."

## 2026-11-22 The MVP is built
*tags: mvp, acceptance-tests, trial, skill, limits, open-items*

- The MVP is on `main`: the cli-tool, the controller, the skill, and a Go test for each of its 127 acceptance tests in `acceptance/`.
- The "done when" of the MVP was met: in a real Claude Code session, one paste and one `y` ran a command and the AI got the output. The skill was read from `skill/gangway/SKILL.md` for it, not installed as a skill.
- The terminal shows no line about the end of a command that ended by itself. The AI still gets the exit code.
- Three acceptance tests of the MVP's requirements have no Go test, because the feature is not built: `GATE-10.5` and `SHOW-03.3` need file reads, `CTL-02.2` needs the login. They are listed in `acceptance/ids_test.go`.
- `LIM-06.1` reads the starting limits from `hello` and does not wait for them: waiting took two minutes on every run on GitHub.
- Known limits of the MVP, each closed by a later step:
  - `stop` works only after "still running". To stop a command earlier, the AI hangs up.
  - Any program on the same machine can start a session with the controller. It gets only its own session. Closed by pairing.
  - The controller holds all output of an open call in memory, with no cap. Closed by the size cut.
- Next: the "After" column of the MVP table in `plan.md`. The order is not decided.

## 2026-11-23 Step 2 ran on a real Tailscale network

*tags: step-2, tailscale, trial, deploy*

- The "done when" of step 2 was met: the controller ran on a server on the internet, behind nginx with HTTPS, and a host with no Tailscale installed reached it over the real Tailscale network. An AI ran two commands, each after one `y`.
- The controller's Tailscale key must be reusable. A one-time key was refused at every start ("invalid key: unable to validate API key"); a reusable one worked at once. Why the one-time key failed at its first use is not known.
- Both programs now show what Tailscale said when it refuses a key. Before, the reason was dropped and the cause could not be found.
- The script that puts the controller on a server is not in this repo. It is in the `vps-automation` repo, on branch `gangway`: it builds the controller from the newest `main`, copies it over, runs it as a service of a plain user on localhost, and sets up nginx. This is for now. Open: a way to build and deploy with nobody running a script.
- Chats on the web could not call the API: they cannot send a POST with a header. The limit is accepted and is in the README. An MCP door may be added later, next to the API.
